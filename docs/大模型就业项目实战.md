## 2. 其他项目
### 2.1 经营归因分析系统
- 项目目标：实现一个面向企业核心经营场景的智能多维归因分析系统，结合指标树因子拆解、自动假设生成、统计检验验证与大事件因果关联，支持围绕经营指标异常波动展开多轮下钻追问、反事实仿真与归因报告导出，输出具备量化贡献率与落地策略的深度经营洞察
- 交付形式：提供可运行前端（三栏交互式归因工作台）、后端服务（含统计检验与代码沙箱执行器）、示例多维数仓数据集、典型大促与经营异动仿真案例、多格式报告导出模块与完整分析演示链路

#### 2.1.1 开发范围
- 基础能力：用户统一认证登录、多指标域与业务线管理、多轮探索会话管理、数据源接入、操作审计与运行日志
- 指标建模与因子拆解能力：多层级指标树构建、加法/乘法模型贡献率分解（LMDI、Shapley 价值分解、杜邦分析法）、多维交叉下钻（时间、渠道、区域、品类、客群）
- 智能假设与验证引擎：基于大语言模型与统计算法自动生成归因假设、调用安全数据沙箱执行 SQL/Python 统计验证、相关性检验、变动贡献率定量核算、排除伪相关干扰
- 业务大事件因果关联：企业营销日历、运营动作、外部竞品与宏观事件录入与关联匹配，避免机械数值推导，实现业务语境融合归因
- 决策仿真与建议生成：基于敏感性分析提供 What-If 策略推演（如价格调整或渠道预算重配后的指标预期变动），输出包含责任岗位、行动建议和预期收益的落地策略
- 工作台交互与呈现：多轮探索对话区、指标异动瀑布流图、下钻数据透视表、因果证据链展示、报告在线协同与一键多格式导出（Markdown、PDF、Excel）

#### 2.1.2 用户角色与权限
- `经营分析师`：创建归因会话、设定目标指标、输入探查问题、调优指标拆解逻辑、审核归因证据链、调整 What-If 模拟参数、发布与导出经营分析报告
- `业务负责人 / 管理层`：查看指标异动大盘、查看结构化归因结论与量化贡献率、查看行动项建议、订阅周期性归因简报
- `系统与数据管理员`：维护指标元数据与拆解公式、配置数据源连接、维护业务大事件日历、管理模型调用参数与代码执行沙箱安全配额

#### 2.1.3 页面需求
- `指标异动大盘页`：展示核心经营指标监控看板，突出标识异常波动指标（如日环比跌幅超阈值），提供一键发起“智能归因分析”快捷入口
- `归因分析工作台`：
  - `会话与指标导航区`：展示历史归因会话列表与当前目标指标概览，支持切换会话与新建分析
  - `对话与探索交互区`：支持自然语言输入分析意图与多轮追问，流式展示分析路径、数据沙箱验证过程与统计结论
  - `动态归因看板区`：展示因子贡献瀑布图、多维下钻透视表、核心归因结论卡片与落地行动项，支持 What-If 参数推演与一键导出报告
- `业务事件日历页`：维护企业营销节点、大促活动、系统故障、政策变化等事件记录，支持按时间线与指标域筛选
- `指标字典配置页`：维护原子指标、派生指标、复合指标公式与默认拆解层级树
- `报告归档与导出预览页`：提供整篇分析报告的排版预览，支持批注编辑、导出 PDF、Excel、Markdown

#### 2.1.4 归因分析方法论与业务规则
- 指标拆解与贡献率测算规则：
  - 加法模型指标（如 利润 = 营收 - 成本）：采用差额分析法计算各组成因子的绝对变动与贡献率
  - 乘法模型指标（如 销售额 = 访客数 × 转化率 × 客单价）：采用对数平均迪氏指数法（LMDI）分解，确保各因子贡献量之和严格等于总指标变动量，消除交叉残差
  - 维度下钻贡献率：采用 Shapley 价值或占比贡献法，核算各细分维度（如各省份或各品类）对整体大盘波动的拉动率
- 假设生成与双向验证规则：
  - 系统根据指标异动特征并行生成多条归因候选假设（如“大盘转化率下降由高流量低转化渠道占比提升引起”或“某品类断货导致客单价下滑”）
  - 每次假设验证必须生成可执行数据探查代码，并在受控沙箱中执行，产出量化事实与置信度，置信度低于阈值的假设自动标记为“已排除”
- 业务大事件因果关联规则：
  - 探查指标异常波动时，系统自动匹配异动时间窗口前后 3 日内的业务日历事件
  - 若事件与指标变动在时间、品类或渠道上重合，系统将该事件作为外生解释变量引入归因因果链，防止将外部干扰误判为内部操作问题
- 落地策略可执行性规则：
  - 系统给出的下一步建议必须绑定量化驱动因子，明确指出责任角色、预期恢复周期与预期挽回金额，严禁输出泛化无依据的建议

#### 2.1.5 前端模块要求
- `工作台框架与会话模块`：管理左中右三栏弹性布局、折叠展开状态、历史会话切换与实时任务断点保持
- `实时交互与思维链流式模块`：负责自然语言解析结果、执行规划步骤、假设卡片流、工具调用状态的流式渲染
- `数据可视化引擎模块`：基于图表库构建因子贡献瀑布图、指标杜邦拆解树、下钻时序趋势图与桑基图
- `动态透视表模块`：支持多维层级折叠、列头排序、差额高亮染色与一键导出当前表格
- `What-If 仿真器模块`：实现客户端驱动因子的交互式滑块调参、敏感度曲线实时重算与情景对比呈现
- `报告组装与导出模块`：将分析会话中的图表、结论、数据表一键组装为标准化经营简报，支持一键打印与导出

#### 2.1.6 后端与分析引擎模块要求
- `指标体系与公式引擎模块`：管理指标元数据、层级树关系，执行加法/乘法模型的动态代数分解
- `意图理解与规划调度模块`：解析用户归因分析意图，动态规划分析步骤（识别异动 -> 指标拆解 -> 维度下钻 -> 假设生成 -> 统计检验 -> 业务归因 -> 策略建议）
- `安全数据分析沙箱模块`：提供受限只读的数据查询与脚本分析计算环境，执行动态统计脚本、LMDI 分解与假设检验
- `因果关联与知识引擎模块`：检索业务事件日历与历史归因库，计算事件与指标异常的相关度，生成因果解释链
- `敏感性模拟与建议引擎模块`：基于弹性系数与历史波动率构建 What-If 推演模型，输出多情景预测与优先建议
- `会话状态与报告管理模块`：负责多轮分析上下文维护、中间快照持久化、分析报告结构化落库与导出

#### 2.1.7 核心业务流程
- `指标异动发现与归因发起流程`：
  1. 用户在监控大盘发现关键指标异常，或在工作台输入自然语言归因需求
  2. 系统解析目标指标、时间范围与对比基期（如同比、环比、目标差）
  3. 系统读取指标树定义，完成第一级核心因子数学拆解与大盘拉动率计算
- `假设生成与多维下钻验证流程`：
  1. 引擎根据因子异动幅度生成 3~5 个候选归因假设，并在界面呈现假设看板
  2. 引擎为各假设编写沙箱验证代码，并行执行维度交叉探查（按渠道、人群、品类拆解）
  3. 过滤无关假设，筛选出贡献率超过显著性阈值的核心因子与异动维度
  4. 检索大事件日历，匹配营销大促、系统故障等外部解释变量，补全因果链条
- `多轮交互追问与深度探查流程`：
  1. 用户针对阶段性结论发起追问
  2. 系统继承前序分析上下文，锁定异常切片，进一步向下钻取细分指标与底层行为数据
  3. 系统动态更新归因看板与证据透视表，生成深层原因结论
- `What-If 模拟推演与报告产出流程`：
  1. 系统基于归因结果锁定可干预驱动因子，生成优化策略候选方案
  2. 用户在模拟器调节参数，系统实时推演目标指标预期变动幅度与收益区间
  3. 系统组装指标异动、量化归因、证据图表、模拟结果与策略建议，生成完整结构化经营归因报告并支持导出

#### 2.1.8 报告与输出格式规范
- `异动背景与问题定义`：说明目标指标、统计周期、基期值、现期值、总差异额与差异率
- `因子贡献率拆解`：以瀑布流图与表格列出各驱动因子的绝对贡献值、贡献率百分比与拉动方向
- `细分维度下钻证据`：展示异动最集中的 TOP 维度组合、明细数据透视表及关键变化特征
- `核心归因结论`：结构化阐明导致异动的首要原因、次要原因及内外部诱因
- `因果证据链与检验置信度`：列出数据验证证据、代码执行结果与统计显著性水平
- `What-If 情景模拟结论`：给出不同调优策略下的目标指标预估改善空间
- `可落地策略行动清单`：输出明确的业务整改动作、责任岗位、预估完成周期与预期业务收益

#### 2.1.9 示例业务场景与基准数据集
- `电商 GMV 下滑归因`：提供订单表、商品表、类目表、流量与转化漏斗表、促销活动表，分析 GMV 波动中流量因素、转化因素与客单价因素的贡献度
- `快消品利润率异动归因`：提供营收表、原材料成本表、物流履约表、渠道佣金表，分析毛利率与净利率波动的成本驱动与价格驱动
- `SaaS 订阅续约率异常归因`：提供客户分层表、产品功能活跃日志、工单支持表、销售跟进表，分析客户流失的关键断点与功能瓶颈
- 至少选定两个典型场景完成全链路真实数据模拟与分析演示

### 2.2 舆情分析平台
- 项目目标：实现一个面向企业品牌与公共事件的智能舆情分析平台，支持全网多源（社交媒体、新闻门户、短视频平台、行业论坛等）内容监测与多模态解析，利用大语言模型与 NLP 算法提供舆情态势感知、情感倾向识别、风险预警、传播脉络溯源与核心观点聚类，并自动生成结构化舆情研判报告与公关应对建议
- 交付形式：提供可运行前端（态势大屏与研判工作台）、后端分析服务、模拟多源舆情数据集（文本、图片 OCR 文本、音视频转录文本）、典型舆情事件分析案例、报告导出功能与完整演示链路

#### 2.2.1 开发范围
- 基础与监测配置：用户登录、监测主题与关键词维护、信源通道开关、预警阈值与通知渠道配置
- 数据接入与多模态解析：公开信源采集与模拟数据接入、图文 OCR 识别、音视频 ASR 转录接入、文本清洗与 SimHash 去重
- 舆情认知与研判分析：情感倾向与细粒度情绪识别、风险等级评估（S/A/B/C 级）、热点实体抽取与关联图谱、传播脉络溯源时间线、核心观点聚类与意图提炼
- 预警告警与协同处置：突发舆情与敏感事件实时预警、告警消息推送、处置状态流转（跟踪、已核实、辟谣处理、忽略）、公关应对策略与回应话术草案生成
- 研判报告与交付呈现：自动化生成结构化舆情事件研判报告、多维数据图表看板、报告在线预览与多格式导出（PDF、Markdown）

#### 2.2.2 用户角色与权限
- `舆情分析师`：创建与调整监测主题、查阅舆情动态流、进行事件研判与观点下钻、生成与导出研判报告
- `公关运营人员`：接收突发高危预警、查看事件传播脉络与核心观点、采纳公关应对建议、流转处置工单
- `系统管理员`：配置信源采集通道、设定预警分级阈值与通知渠道、维护系统运行配置

#### 2.2.3 页面需求
- `舆情态势大盘页`：展示全网舆情声量趋势图、情感倾向分布（正/中/负占比）、实时风险预警动态滚动列表与热点词云
- `舆情研判工作台`：
  - `监测流与筛选区`：展示多源舆情动态流卡片，支持按主题、信源渠道、时间跨度、情感标签与风险等级多维筛选
  - `事件分析与溯源区`：展示选定事件的传播溯源时间线、核心争议观点聚类、实体关系图谱与多模态原文详情
  - `处置协同与应对区`：支持风险等级人工复核、处置动作标记（已处理/跟踪中/辟谣处置）与大模型公关回应草案生成
- `报告中心页`：展示周期性舆情简报与突发事件专项报告列表，提供报告在线预览与导出功能
- `监测配置页`：维护监测主题词包、信源接入开关与预警告警阈值规则

#### 2.2.4 舆情分析与研判规则
- 内容清洗与聚类规则：
  - 采用 SimHash 指纹算法识别高度重复内容与水军刷量信息，合并同质内容
  - 对同一事件关联讨论按语义相似度执行聚类，归纳为单一事件主题
- 情绪识别与风险评级规则：
  - 基础情绪划分为正向、中性、负向，负向情绪细分识别愤怒、失望、恐慌、质疑等标签
  - 结合传播扩散速度、互动量（转评赞）、KOL 账号权重与敏感词命中情况，综合计算舆情烈度指数，划分为 S（极高危）、A（高危）、B（中危）、C（低危）四级
- 传播溯源与实体关联规则：
  - 按发布时间对聚合事件内容排序，识别首发信源节点与关键引爆扩散节点
  - 抽取机构、人物、产品、事件等核心实体，构建传播关联链路图谱
- 预警触发规则：
  - 单小时负向舆情声量环比激增超过阈值，或命中高危敏感词/高权重账号发声时，立即触发实时告警
- 应对建议生成规则：
  - 依据事件性质（质量争议、服务纠纷、合规风险等）与公众诉求核心，利用大模型生成包含事实澄清、情绪疏导与行动方案的响应策略

#### 2.2.5 前端模块要求

- 案件流转与协同处置：高危事件或待审事件自动沉淀为风控案件，提供多维画像下钻、作弊证据链呈现、关联团伙图谱分析、一键处置（拦截订单、拉黑账号、封禁设备）与操作审计
- 策略配置与名单管理：规则增删改查、阈值评分配置、规则启停用控制、多维度名单库（用户、手机号、IP、设备、地址）统一维护
- 运营监控与模拟排查：实时风控态势监控、规则命中排行、资损防护统计，提供事件在线仿真模拟测试工具

#### 2.3.2 用户角色与权限
- `风控审核员`：查看待审风控案件、核对行为证据链与关联图谱、录入人工复核结论并执行业务处置
- `风控策略师`：配置与调整风控规则集、调整规则权重与判定阈值、维护多维名单库、执行策略回测与仿真分析

- `风控态势大盘页`：展示实时事件请求量、拦截率趋势折线图、风险等级分布环形图、规则命中排行榜与预估挽回资损卡片

  - `案件筛选与列表区`：支持按风险等级、事件场景、审核状态、触发时间筛选案件，展示待审工单列表与简要风险标签
  - `证据链与画像详情区`：展示涉事用户全貌画像、当前订单信息、实时特征快照对比及关联实体图谱（同设备/同 IP/同地址聚集账号）
  - `研判与处置协同区`：展示系统风险判定摘要与证据提示，提供处理结论选择（放行/拦截/拉黑）、处置原因备注与一键执行按钮
- `策略与规则配置页`：展示风控规则列表（支持按场景分类、启停状态切换、权重分值修改与条件表达式编辑），内嵌多维名单库管理标签页（黑/白/灰名单维护与批量导入）

#### 2.3.4 风控决策与流转规则
- 事件接入与特征构建规则：
  - 支持 `login`、`coupon_receive`、`order_create`、`order_pay`、`after_sale_apply` 五类事件
  - 动态计算滑动窗口统计特征（如近 1 小时同设备下单次数、近 24 小时同收货手机号退款率、同 IP 注册账号数等）
- 决策评级与仲裁规则：
  - 白名单命中直接判定为放行（Pass），黑名单命中直接判定为拦截（Reject）
  - 规则集按分值累加机制计算风险综合得分（0~100 分）：
    - 0~59 分：判定为低风险（Pass，正常放行）
    - 60~79 分：判定为中风险（Review，生成人工审核案件或触发二次验证）
    - 80~100 分：判定为高风险（Reject，直接拦截交易并自动创建风险案件）
- 案件生成与协同处置规则：
  - 判定结果为 Review 或 Reject 时，系统自动生成风控调查案件
  - 审核人员完成案件处置后，系统联动更新业务订单状态（如取消未支付订单、拒绝售后退款申请），并将处置过程记入不可篡改的审计日志

#### 2.3.7 核心业务流程
- `实时交易风控检测流程`：
  1. 业务系统发起订单或支付等关键操作时，调用风控系统传入事件参数
  2. 风控系统执行黑白名单快速过滤，并行计算实时上下文特征快照
  3. 规则引擎依次执行策略判定，累加命中规则分值，得出最终风险等级与决策动作
  4. 系统同步返回决策结果（放行/拦截），并将全量特征快照与命中记录异步持久化
- `高危案件调查与处置流程`：

  3. 审核人员确认违规事实后，选择“违规拦截并拉黑用户”，录入核查依据并确认提交
  4. 系统自动执行处置动作，同步拦截关联订单并将涉事主体加入黑名单库
- `风控规则上线与调优流程`：
  1. 策略师在策略配置页创建或编辑风控规则，设定触发条件与风险分值
  2. 在仿真测试页载入典型历史作弊样本，验证规则命中效果与误伤情况
  3. 验证无误后开启规则，新规则立即对线上实时事件生效

- 任务状态流转规则：

  - 回写状态包含 `not_written`（未回写）、`writing`（回写中）、`success`（回写成功）、`failed`（回写失败）
  - 遇到文档加密、扫描件严重模糊或正文为空时，任务流转为 `blocked` 并记录原因，支持人工重新上传或一键重试
- 条款提取与元数据解析规则：
  - 自动提取签约主体名称、统一社会信用代码、合同金额、币种、履行期限、生效条件等核心元数据
  - 逐段切分标的物条款、付款进度、验收标准、违约责任、保密义务、数据安全、争议解决管辖等法定与业务条款
  - 每个解析项必须记录原文起止字符位置、页码与段落索引，确保双向可溯源定位
- 合规审查判定规则：
  - 综合风险等级分为高风险、中风险、低风险三级
  - 命中以下情形直接标记为高风险：主体信息缺失或被列入经营异常、违约责任严重不对等（如我方单方承担无限责任）、管辖地约定违规、未设置付款前置验收条件
  - 命中以下情形标记为中风险：缺少保密义务期限、未明确不可抗力通知时效、违约金比例超出法定合理范围
  - 针对每个风险点，大模型自动输出替代修改方案（如建议修改为“双方各承担 50%”或“违约金不超过合同总额的 20%”）

### 2.5 自动化安全评估系统
- 项目目标：实现一个面向代码工程的自动化安全评估系统，结合多智能体（Multi-Agent）协同架构与沙箱隔离技术，自动化完成源码扫描、污点链路分析、动态无害 PoC 验证、多步攻击路径推演，输出可复现漏洞证据、修复补丁与专业安全评估报告
- 交付形式：提供可运行前端（评估看板与审计工作台）、后端服务（含多 Agent 调度编排与安全沙箱执行器）、示例靶场源码工程集（含已知典型高危漏洞）、评估报告导出功能与完整演示链路

#### 2.5.1 开发范围
- 项目接入与沙箱隔离：支持 Git 仓库克隆与本地压缩包源码上传，自动识别技术栈依赖，提供只读安全容器沙箱执行分析与验证命令
- 多智能体协同审计：编排环境侦察、静态代码审计（SAST）、动态 PoC 验证与攻击路径推演四类专业 Agent，实现全自动端到端评估流水线
- 漏洞发现与精准验证：覆盖注入攻击、越权访问、远程代码执行（RCE）、反序列化、敏感信息泄露等高危类型，通过动态沙箱执行无害验证 PoC，剔除静态分析误报
- 攻击链拓扑与补丁生成：自动分析单点漏洞的组合可利用性，构建多阶段攻击拓扑链路图，基于大模型生成代码修复补丁（Diff 格式）
- 报告交付与实时监控：流式呈现评估执行过程与实时运行日志，自动汇编结构化安全审计报告，支持 PDF、HTML、Markdown 导出

#### 2.5.2 用户角色与权限
- `安全工程师 / 审计人员`：创建评估任务、监控 Agent 审计过程、核对漏洞验证证据与攻击拓扑链、审核修复建议并导出报告
- `研发人员`：查看项目扫描结果、比对漏洞定位与污点传播轨迹、采纳 AI 修复补丁
- `系统管理员`：维护安全沙箱容器镜像、配置超时时间与资源配额、管理大语言模型推理参数与系统审计日志

#### 2.5.3 页面需求
- `项目概览大盘页`：展示所有代码工程的评估状态列表（项目名称、技术栈、最新评估时间、高/中/低危漏洞数），提供“新建评估项目”快捷弹窗
- `安全评估工作台`：
  - `流水线与执行监控区`：展示多 Agent 阶段推进看板（环境侦察 -> 源码审计 -> 动态验证 -> 路径推演 -> 报告生成）、实时终端日志流与资源消耗指标
  - `漏洞与攻击链路区`：展示已发现漏洞列表（标记 CVSS 评分、漏洞分类与验证状态 Verified/Unverified），提供多步渗透攻击路径拓扑关系图
  - `漏洞详情与修复区`：展示漏洞触发代码行定位、污点输入至漏洞汇聚点（Source-to-Sink）传播轨迹、PoC 验证请求与响应报文，提供 AI 生成的代码修复补丁 Diff 对比
- `安全报告中心页`：以合规文书样式排版展示评估报告全文，包含风险评级大盘、漏洞综合分析、攻击路径说明与整改修复清单，支持一键导出多格式报告
- `沙箱与环境配置页`：维护安全沙箱镜像环境、网络隔离策略、扫描超时限制与并发任务数

#### 2.5.4 评估流程与判定规则
- 执行阶段与状态流转规则：
  - 项目评估状态包含 `created`（已创建）、`running`（评估中）、`completed`（评估完成）、`failed`（执行失败）、`stopped`（已停止）
  - 任务阶段按顺序推进：`recon`（环境侦察）-> `code_audit`（源码审计）-> `poc_verify`（动态验证）-> `exploit_chain`（路径推演）-> `report_gen`（报告生成）
  - 终止任务时，安全沙箱立即注销正在执行的测试进程，但持久化保留已产出的阶段性漏洞数据
- 静态污点与动态验证判定规则：
  - 静态审计基于语义分析提取外部输入 Source 点与敏感函数 Sink 点，存在未经过滤的数据流向时标记为疑似漏洞（Unverified）
  - 漏洞验证 Agent 在隔离沙箱中针对疑似漏洞发送无害化探针，只有获取到预期特征响应时，才将状态转为已验证（Verified）
  - 未通过 PoC 验证但存在风险模式的代码，标为中低危潜在隐患，防止误报干扰
- 攻击链路推演规则：
  - 存在多个关联漏洞时，系统依据资产权限跃迁逻辑（如未授权访问 + 文件上传 -> RCE）进行链式组装，绘制有向无环图（DAG）攻击路径

#### 2.5.7 核心业务流程

  1. 用户在概览大盘输入 Git 地址或上传源码包，启动自动化安全评估

- `报告导出与归档流程`：

- 投放策略与合规边界：生成人群定向、出价策略与 A/B 实验建议方案，严格通过人工审批确认机制流转，不直接操作外部广告账户与资金扣费
- 经营数据回填与闭环复盘：支持单品经营数据（GMV、曝光、转化率、ROI）手工录入与批量表格导入，自动生成经营复盘报告并沉淀下一轮迭代策略

#### 2.6.2 用户角色与权限
- `运营人员`：维护商品与竞品信息、发起智能诊断与创意生成任务、审核素材、确认投放建议、回填经营数据并查看复盘报告
- `运营主管 / 管理员`：审核高风险投放实验方案、管理店铺授权配置、维护大模型参数与异步任务队列并发配额

  - `商品档案与竞品诊断区`：展示当前商品基础信息、多平台规格映射、竞品对比明细与 AI 商品诊断看板（卖点提炼、转化痛点、定价建议）
  - `内容创意与素材生成区`：展示多方向主图设计方案与短视频带货脚本，提供一键发起异步生图/生视频任务、生成任务状态时间线与素材库列表

#### 2.6.4 业务闭环与生成规则
- 单品运营全链路闭环规则：
  - 业务流转严格遵循：`商品建档与竞品录入 -> 智能诊断 -> 创意方案生成 -> 异步素材制作与审核 -> 投放策略建议与确认 -> 经营数据回填 -> 闭环复盘报告`
  - 诊断结论、创意方案、素材记录、投放计划与复盘报告必须严格绑定归属单品，复盘结论中的优化建议可一键转入下一轮商品诊断
- 结构化生成与可编辑规则：
  - 商品诊断必须结构化包含目标客群、价格带分析、核心卖点矩阵、转化卡点与优化方向
  - 主图方案必须至少输出 3 组差异化方向，每组包含构图版式、核心文案、主打卖点与视觉呈现建议
  - 视频脚本必须至少输出 3 套结构化分镜脚本，包含开头 3 秒黄金钩子、分镜画面描述、口播台词与促单转化话术
  - 所有 AI 生成内容必须支持运营人员在线修改、确认或归档，严禁只读不可编辑
- 异步生成任务控制规则：
  - 图像与视频生成任务采用异步队列解耦，包含 `pending`（排队中）、`running`（生成中）、`succeeded`（生成成功）、`failed`（失败）、`timeout`（超时）状态
  - 任务支持超时主动检测、失败重试与人工主动取消，执行状态通过前端轻量轮询或事件流实时回传
- 合规安全边界规则：
  - 平台账号仅保存接入标识与脱敏授权状态，严禁存储明文密码或 Cookie
  - 投放建议仅作为运营决策参考，严禁直接调用外部接口自动发起线上扣费与广告计划创建

#### 2.6.7 核心业务流程
- `商品建档与诊断生成流程`：
  1. 运营人员录入商品基础属性或通过导入中心批量导入
  2. 录入竞品信息并补充竞品核心参数
  3. 系统调用大模型生成结构化商品诊断，提炼产品核心优势与改良方向
- `创意生成与素材制作流程`：
  1. 运营人员基于诊断结论一键触发创意方案生成
  2. 系统输出多组主图设计方案与短视频脚本，运营人员选定并微调内容
  3. 运营人员提交素材生成任务，系统入队异步处理，前端展示实时任务状态
  4. 生成完成后素材自动落入商品素材库，运营人员核验并标记为可用
- `投放策略确认与经营复盘流程`：
  1. 系统结合商品定位与素材特性输出投放实验建议（人群、出价、素材组合）
  2. 运营主管审核建议，标记“确认采纳”或“驳回调整”
  3. 投放周期结束后，运营人员回填实际曝光、点击率、转化率与 GMV 数据
  4. 系统对比预期目标与实际数据，自动生成经营复盘报告，指出核心波动归因并给出后续优化行动项

#### 2.6.8 报告输出格式
- `单品全景信息`：商品名称、所属品类、在售价格带、主推 SKU 与对标竞品概要
- `智能诊断总结`：目标客群定位、核心卖点矩阵、转化卡点与价格竞争力评估
- `视觉与内容资产`：已采纳主图设计方案、已选定短视频分镜脚本与关联优质素材清单
- `投放实验记录`：建议策略内容、审核确认人、审批时间与执行备注
- `经营复盘与后评价`：核心经营指标对比（目标 vs 实际）、流量与转化归因总结、后续迭代行动建议

### 2.7 财务单据智能风险审核系统
- 项目目标：实现单据全生命周期管理、多模态凭证解析、自动化交叉核对、智能风控分析、双轨人机复核与报告导出的财务风控系统
- 交付形式：提供可运行前端控制台、后端业务与分析服务、OCR 与大模型适配层、示例单据凭证集与端到端审核演示链路

#### 2.7.1 开发范围
- 单据与凭证覆盖：支持对公付款单、预付款单、批量付款单、费用报销单与差旅报销单五类业务单据；支持增值税发票、电子客票、采购合同、银行回单与行程水单等凭证解析（PDF、PNG、JPG 格式）
- 多模态凭证结构化抽取：集成 OCR 与多模态大模型抽取发票代码、发票号码、金额税额、开票日期、购买方与销售方、合同条款及付款条件，建立原文档坐标级锚点与置信度标注
- 自动化智能风控核验：实现金额交叉比对（单据总额 vs 明细合计 vs 发票金额 vs 合同付款比例）、费用标准合规校验、市场公允价偏差探查、重复报销排查、消费异常行为识别与供应商信用风险排查
- 交互复核与决策工作台：提供单据详情、凭证原文与风控看板三位一体工作台，支持高风险疑点证据链高亮跳转、财务人工批注、补充材料退回与审批流转
- 报告与数据沉淀：生成多维度单据智能风控审查报告，支持一键导出 PDF/Excel，沉淀全链路审计轨迹

#### 2.7.2 用户角色与权限
- `单据申请人`：创建与编辑单据、维护明细、上传凭证附件、提交审批、撤回待审单据、查看审核进度与补充材料
- `财务初审员`：查看待审单据队列、使用核对工作台进行人机协同审核、标记风险疑点、录入复核意见、发起退回或转交复审
- `财务主管 / 审批人`：审查高风险单据、终审大额付款与异常违规单据、执行审批通过或驳回、配置审批流转规则
- `系统管理员`：维护标准费用额度、市场参考价基准库、供应商风险黑白名单、模型与 OCR 接口参数及全量审计日志

#### 2.7.3 页面需求
- `财务风控总览大盘`：展示待审单据概览、高频风险类型排行、单据金额分布、拦截违规金额统计与近期待办任务列表
- `单据台账与管理页`：提供五类单据的多条件筛选（编号/类型/部门/金额/风险等级/状态）、批量导入、单据新建/编辑抽屉、状态追踪与单据快照对比
- `智能风控审核工作台`：
  - `单据结构化详情区`：展示单据基本信息、明细分解、申请事由、经办流转记录与当前审批节点
  - `凭证原文与 OCR 证据区`：展示多格式凭证原件预览、提取字段列表、识别置信度与证据链坐标高亮锚点联动
  - `风控诊断与交叉核对区`：展示五维金额交叉对比面板、风险项分类列表（严重/中度/提示）、判断依据与规则阈值，提供人工确认/忽略、复核批注与审批操作按键
- `风控规则与标准配置页`：维护各部门差旅与业务招待费限额标准、市场价波动容差阈值、发票查重时间跨度、供应商风险名录与审批流节点配置
- `报告中心与审计追溯页`：提供审核报告列表检索、一键在线预览与 PDF 导出，记录全流程操作轨迹与数据变更日志

#### 2.7.4 核心核验规则与风控体系
- 多维金额交叉核对规则：
  - `单据与发票核对`：比对单据申请金额与关联发票价税合计金额，计算绝对差额与偏离比例
  - `明细与总额校验`：汇总单据各项支出明细金额并与单据申请总金额比对，自动标记漏项与算术差额
  - `合同与付款核验`：校验付款申请与关联合同条款的付款比例、履约节点、累计已付金额是否超出合同总限额
  - `批量付款防重核验`：校验批次内收款账号与付款明细，标记重复收款人、重复单笔金额与批次汇总差异
- 费用标准合规与公允价探查规则：
  - `差旅与招待限额标准`：按出差城市等级、职级标准对比交通费舱位、住宿费限额与每日补贴标准，标记超标金额
  - `市场公允价偏离探查`：按采购物资或服务名称规格比对基准市场价区间，偏离度超过设定容差阈值触发溢价预警
- 欺诈与异常行为识别规则：
  - `重复报销排查`：跨单据全局比对发票代码、发票号码、开票日期与金额，杜绝一票多报
  - `消费异常模式探查`：检测同日连号发票、非工作日大额消费、异地突发消费、临近额度上限拆单报销行为
  - `供应商信用风险联动`：自动匹配供应商工商存续状态、经营异常名录、严重违法失信记录及近期高频变更账号

#### 2.7.5 前端模块要求
- `大盘与台账模块`：处理指标卡片、风险分布图表、单据多维检索、分页表格与新建/编辑抽屉表单
- `工作台核心视图`：支持三栏自适应联动布局，实现单据结构化数据、多模态凭证原文预览与风控面板同屏协作
- `凭证与证据锚点组件`：处理 PDF/图片多格式渲染、OCR 识别框与字段值联动高亮、坐标反查与置信度标识
- `核对与审批交互模块`：处理金额差异对照表展示、风险项状态切换（待定/已确认/已忽略）、审批批注输入与流转动作
- `规则配置与报告模块`：提供费用阈值表单编辑、供应商名单管理、富文本审核报告预览与一键导出功能

#### 2.7.6 后端模块要求
- `单据生命周期引擎`：负责五类单据的增删改查、草稿暂存、版本快照沉淀、流转状态机驱动
- `多模态文档解析服务`：调度 OCR 识别与多模态大模型抽取凭证结构化字段、计算置信度并输出版面归一化坐标
- `规则与核验计算引擎`：执行金额交叉比对、费用标准比对、基准市价偏差探查、历史发票去重校验与异常行为模式过滤
- `风控综合评估模块`：汇总规则计算结果与外部征信数据，判定单项与整体风险评级，组装证据链与处置建议
- `审批流与审计中心`：驱动多级审批流转、支持退回重审与加签，全量记录用户操作、规则版本与复核轨迹

#### 2.7.7 核心业务流程
- `单据填报与凭证解析流程`：
  1. 申请人选择单据类型，录入抬头、事由与支出明细
  2. 申请人上传相关发票、合同或报销水单等凭证附件
  3. 系统触发后端多模态解析流水线，异步完成 OCR 与字段提取，生成结构化凭证元数据与坐标锚点
- `自动化核验与风控评估流程`：
  1. 申请人确认信息无误后提交单据
  2. 系统触发风控规则引擎，并发执行四维金额交叉核对、费用标准比对、重复票据排查与供应商资信校验
  3. 引擎综合评估风险项，生成单据风险等级（无风险/低风险/中风险/高风险）与结构化审查证据链
- `人机协同复核与审批流转流程`：
  1. 财务人员打开智能审核工作台，调阅待审单据
  2. 工作台并排呈现单据明细、凭证原件 OCR 锚点与风险提示
  3. 财务人员针对疑点项进行核验，标记“确认为异常”或“忽略提示”，录入复核意见
  4. 财务人员执行通过、退回申请人补充材料或直接驳回操作
  5. 终审完成后系统生成不可变审查归档记录与风险审计报告

#### 2.7.8 风险报告输出格式

#### 2.8.4 核心协议与契约治理体系
- 控制面与数据面分离：FastAPI + LangGraph + Celery + PostgreSQL 负责控制面治理，Apache SeaTunnel 负责数据面搬运，控制面不直连搬运海量业务数据
- 三层状态隔离机制：
  - 对话状态（Conversation State）：记录自然语言交互历史
  - Agent 状态机（Workflow State）：LangGraph 管理需求澄清、生成、门禁校验与有限修复，通过 Checkpoint 跨请求持久化与恢复
  - 底层执行状态（Execution State）：记录实际任务运行实例（ExecutionRun）、SeaTunnel 作业 ID 与指标
- `prepare → approve → commit` 三阶段执行协议：
  - `Prepare` 阶段：推导输入指纹、资源范围、影响范围、数据分级、运行预算与回滚方案，冻结生成不可变 Preparation 准备单，不产生外部副作用
  - `Approve` 阶段：具名审批人基于冻结事实执行独立审批，强制四眼原则与职责分离
  - `Commit` 阶段：服务端重新校验指纹与审批事实，签发 Ed25519 签名短时单次 Capability 令牌，经 Tool Broker 在同一事务中原子创建 ExecutionRun 与 Outbox 投递命令
- 防重放与单次能力规则：Capability 令牌绑定工具、主体、环境与制品指纹，有效期 5 分钟且由 Replay Guard 保证仅消费一次
- 质量契约与原子发布规则：
  - 质量契约（QualityContract）：声明字段级清洗过滤规则与错误码标签，数据面执行时将未命中规则的数据分流写入错误表，记录原始值与违规原因
  - 运行时监督契约（RuntimeSupervisionContract）：冻结最大读取行数、最大写入字节数、最大执行时长预算，监控输出放大比与错误拒绝率，超限触发硬中断
  - 影子表原子 Swap：有效数据写入影子表，质量报告校验通过后通过原子 Swap（如 Doris `REPLACE TABLE ... swap=true`）无缝替换为正式表

#### 2.8.5 前端模块要求
- `连接与 Profile 管理模块`：处理数据连接表单、连通性测试、元数据安全探查与脱敏样本渲染
- `Pipeline Studio 交互模块`：处理自然语言提示词输入、LangGraph 澄清交互、HOCON 语法高亮与 DAG 图形化渲染
- `不可变版本与 Diff 模块`：对比不同 Pipeline 版本的 Schema、HOCON 配置与质量规则差异
- `审批流与准备单模块`：展示 Preparation 冻结事实、影响分析、回滚方案与具名审批操作卡片
- `运行监控与指标模块`：轮询或订阅执行状态、展示吞吐曲线、质量分流统计与可解释诊断面板
- `安全治理与评测模块`：展示 Benchmark 测评用例集、触发评测并渲染安全指标大盘

#### 2.8.6 后端与 Harness 核心模块要求
- `API 控制面服务`：提供连接、元数据、设计生成、审批、执行与运行监控服务
- `LangGraph 编排引擎`：构建可恢复的 ETL 生成状态机（意图解析 → 元数据探查 → 生成 EtlPlan/HOCON → 确定性门禁 → 试运行 → 准备审批）
- `Harness 安全执行内核`：
  - `Policy Decision Point (PDP)`：根据 ToolIntent、资源范围、环境与数据分级输出 P0-P3 风险决策与审批要求
  - `Capability Issuer & Verifier`：基于 Ed25519 算法签发与校验单次执行能力令牌
  - `Tool Broker & Replay Guard`：作为所有副作用执行的唯一出口，拦截未授权调用与重放请求
  - `Transactional Outbox`：保证本地业务事实与 Worker 任务投递的原子落库
  - `Evidence Ledger`：维护关键事件的哈希链与签名检查点，保证审计证据不可篡改
- `Celery Worker 执行服务`：接收验签后的受管命令，物化 Secret，调用 SeaTunnel 执行作业并回传状态与指标
- `运行时监督引擎`：依据 RuntimeSupervisionContract 实时监控记录数、字节数、时长、输出放大比与拒绝率，触发预警或硬中断

#### 2.8.7 核心业务流程
- `需求生成与受管发布流程`：
  1. 数据工程师配置源库与目标库连接，生成受管元数据 Profile
  2. 数据工程师在 Studio 输入自然语言 ETL 需求
  3. LangGraph 状态机解析需求，必要参数缺失时触发中断提问，工程师补充后从 Checkpoint 恢复
  4. 模型生成结构化 EtlPlan 与 SeaTunnel HOCON 配置，通过语法编译器与确定性门禁校验
  5. 冻结生成不可变 PipelineVersion 并计算 SHA256 摘要
  6. 调用 Prepare 接口生成准备单，PDP 计算风险等级并分配数据审批人与安全审批人职责槽
  7. 数据审批人与安全审批人分别完成独立审批（四眼原则）
  8. 操作员调用 Commit 接口，服务端校验审批与指纹后签发单次 Capability，写入 Outbox
  9. Celery Worker 消费任务，验签后调用 SeaTunnel 执行数据搬运
  10. SeaTunnel 将有效数据写入影子表，错误数据写入错误表，监督引擎持续监控预算
  11. 质量报告通过后，目标端执行原子 Swap 发布正式表，关键链路生成防篡改证据账本
- `任务中断诊断与受管回滚流程`：
  1. 执行异常或监督超限时触发硬中断，记录失败快照
  2. 诊断服务提取错误堆栈，生成可解释根因说明与修复建议
  3. 操作员发起回滚指令，Harness 验证权限后调用受管清理逻辑恢复原状态

#### 2.8.8 运行报告与审计输出格式
- `Preparation 准备单`：输入指纹、变更资源范围、数据敏感分级、执行预算配额、回滚计划与审批人员列表
- `ExecutionRun 执行记录`：任务 ID、关联 Pipeline 版本 SHA256、执行起止时间、读取行数、写入字节数与平均吞吐速率
- `质量契约与分流报告`：有效数据写入行数、分流错误表数据行数、错误码分布统计（ErrorCode）与规则未命中样本摘要
- `证据账本记录（Evidence Ledger）`：时间戳、操作主体、事件类型、制品哈希、Ed25519 签名与链式前序区块哈希

#### 2.8.9 示例业务场景
- `MySQL 至 Doris 业务宽表增量同步与投产`：数据工程师通过自然语言描述将业务库订单表与用户表在 Doris 汇总为宽表；系统生成 SeaTunnel 配置并提示缺失主键去重逻辑，工程师确认后自动修复；门禁通过后冻结版本，数据审批人核对字段映射无误，安全审批人确认无敏感明文暴露；操作员触发 Commit，SeaTunnel 将有效数据写入影子表，格式异常数据分流写入错误表，校验通过后原子 Swap 上线
- `海量日志同步脏数据超限硬中断与受管回滚`：执行日志清洗入库任务过程中，因源端日志格式突发变更导致错误分流率超过 20% 预算阈值；运行时监督引擎触发硬中断并终止 SeaTunnel 作业，生成根因诊断提示字段类型解析异常；操作员一键触发受管回滚，清理影子表未发布脏数据并释放资源
- 至少任选一个场景完成端到端全流程演示

- `知识管理员`：执行文档导入、编辑、切片调整与删除，配置知识单元的四维数据权限，审核并发布推荐 FAQ，查看并处理知识缺口清单

#### 2.9.4 核心鉴权过滤与知识沉淀体系
- 四维混合数据权限规则：
  - 默认状态下知识单元无任何公开访问权限
  - 每个知识单元支持独立配置四类权限实体：`全局（global）`、`部门（department）`、`角色（role）`、`个人（user）`
  - 权限判定采用充分条件（OR 逻辑）：当用户满足配置的任意一个权限实体时即可读取该知识单元
- AI 检索动态鉴权规则：
  - 智能体回答前必须提取当前会话用户身份、直属部门与所属角色集合
  - 混合检索（向量召回 + 关键词检索）产出候选知识单元后，触发数据权限鉴权过滤
  - 仅将满足权限的知识切片拼接至上下文 Prompt 供大模型生成回答
  - 当召回内容包含用户无权访问的知识单元时，在回答中明确标注“部分参考资料因权限受限无法展示”，严禁越权泄漏未授权内容
- FAQ 聚类沉淀与缓存加速规则：
  - 系统对历史提问日志执行语义去重与频次聚合，达到设定阈值自动生成推荐 FAQ
  - 管理员审核通过后打标上线并同步写入内存缓存
  - 新问答优先匹配 FAQ 缓存，命中时毫秒级直接返回标准答案，降低大模型调用开销
- 知识缺口闭环机制：
  - 检索相似度低于置信度阈值或未命中任何知识切片的问题，自动归入知识缺口池
  - 结合提问频次聚合生成知识建设需求，闭环指导知识管理员补充文档

#### 2.9.7 核心业务流程
- `知识维护与权限配置流程`：
  1. 知识管理员在导入中心上传单个或批量文档
  2. 系统异步完成文本清洗、切片分割与向量嵌入入库
  3. 管理员打开权限配置弹窗，为知识单元配置全局、部门、角色或人员权限
  4. 权限规则即时生效并同步至鉴权引擎缓存
- `AI 鉴权检索与问答流程`：
  1. 登录用户进入对话工作台输入业务咨询问题
  2. 检索服务执行向量与全文混合检索，召回 Top-K 候选知识单元
  3. 鉴权引擎校验当前用户对各候选知识单元的访问权限，执行权限隔离分流
  4. 聚合有权访问的切片生成严谨回答，并在文末附带知识溯源卡片；对无权单元输出权限缺失受限提示
  5. 异步落库问答流水日志，更新看板统计数据
- `知识沉淀与 FAQ 运营闭环流程`：
  1. 挖掘引擎定期分析问答日志，对高频相似提问进行聚类，自动生成候选 FAQ 推荐项
  2. 知识管理员审核推荐内容，在线修正标准问答并点击发布
  3. 系统将通过的 FAQ 注入快速应答缓存
  4. 挖掘引擎汇总未命中提问生成知识缺口项，知识管理员直接基于缺口创建并补充新知识文档

#### 2.9.8 运营分析与审计输出格式
- `单次问答审计记录`：包含会话 ID、用户 ID、提问时间、提问文本、召回单元列表、鉴权通过列表、鉴权拦截列表、消耗 Token 数与响应耗时
- `FAQ 推荐候选卡片`：包含聚类问题簇、聚合提问频次、关联知识单元、推荐标准答案与置信度得分
- `知识缺口诊断清单`：包含未命中提问文本、提问部门、近期出现频次、最高相似度得分与建议创建分类
- `运营效能指标摘要`：包含当日/当周总提问量、独立提问人数（UV）、FAQ 缓存直接命中率、知识库总覆盖率与平均问答延时

#### 2.9.9 示例业务场景

### 2.10 智能商贸提单助手
- 项目目标：实现面向大宗物资与商贸供应链场景的智能提单系统，通过自然语言交互、单据图像识别和表格批量导入，自动完成销售订单与采购订单的关键要素提取、系统字段自动匹配、合同履约额度校验与订单草稿生成，支持悬浮窗与全屏双模态交互，提供一键提单与全流程追溯能力
- 交付形式：提供可运行前端控制台（含内嵌悬浮窗与全屏提单工作台）、后端业务与解析服务、OCR 与大模型适配层、示例商贸数据集与端到端提单演示链路

#### 2.10.1 开发范围
- 基础能力：用户身份鉴权、会话生命周期管理、操作审计记录、草稿暂存与载入、系统参数配置
- 智能提单能力：自然语言意图理解、多轮对话实体抽取、单据图像 OCR 识别与字段结构化、Excel 表格批量解析、物料简称纠错与标准化物料编码映射
- 履约核验能力：合同主数据关联、采销订单关联合验、合同剩余可下订单数与金额动态核算、超额风险预警、必填字段缺失提示
- 商贸协同能力：订单草稿一键生成、预览区字段双向同步、一键正式提单、订单详情抽屉回查、订单列表筛选联动与状态更新
- 双模态交互能力：商贸业务系统内嵌悬浮窗（Floating Widget）、独立全屏提单工作台（Fullscreen Workbench）、视图双向无缝切换

#### 2.10.2 用户角色与权限
- `业务经办人`：发起文本对话提单、上传单据图片、上传批量表格、核对与修改草稿、一键提交订单、查询本人与本部门订单
- `业务审批人`：查看待审订单详情、核对合同额度与超额预警提示、执行订单审核、退回修改或驳回
- `系统管理员`：维护商贸合同主数据与物料编码字典、配置 AI 模型调用参数、配置额度校验规则、查看系统操作审计日志
- 权限隔离规则：提单与提交操作强制校验用户登录态与所属经办部门，禁止越权操作非授权部门单据

  - `订单草稿预览与核验区`：实时呈现草稿状态胶囊（草稿未提交/待确认/已提交）、合同履约额度四项统计指标卡片、超额预警横幅、基本信息网格卡片、产品明细表格与一键提单操作栏

#### 2.10.4 业务规则与履约核验体系
- 自然语言提取与实体补全规则：
  - 提取描述文本中的合同编号、工程项目、物资品名、规格、吨数及交期要求
  - 自动填充固定业务属性（业务名称为“国内传统贸易”、采购模式为“直发”、业务标签为“传统贸易”）
  - 依据当前登录身份自动绑定经办人、经办单位、创建人与创建时间
  - 关键必填要素缺失时在预览区高亮标记待确认状态，并在对话流中主动发起澄清提示
- 单据图像识别与物料纠错规则：
  - 支持发货签收单、磅单、采购合同等单据图片 OCR 结构化提取
  - 针对手写体、俗称与非标简称，自动匹配系统物料词库并纠错映射为标准物料编码与规范名称
- 合同履约配额与超额校验规则：
  - 关联查询合同累计已下订单数、累计已下金额、剩余可下订单数及剩余可下金额
  - 当次订单金额超出合同剩余可用额度时，触发硬性超额警告提示，要求经办人复核并记录预警标识
- 提单防重与幂等规则：
  - 订单正式提交成功后锁定提交按键，防止网络抖动导致的重复提交
  - 生成唯一商贸单据流水编号（如 `XSDD-WZGS-20260318-001`），并将草稿状态推进为已提交

#### 2.10.7 核心业务流程
- `自然语言对话提单流程`：
  1. 经办人在工作台或悬浮窗输入自然语言提单需求
  2. 对话引擎抽取合同号、项目、物料、数量与期望交期
  3. 系统关联商贸合同主数据，补全签约单位、送货地址与经办信息
  4. 系统计算合同剩余额度并实时装配订单草稿预览卡片
  5. 经办人核对草稿并补充必要字段
  6. 点击一键提单，系统生成正式订单编号并写入商贸数据库
- `单据图片 OCR 提单流程`：
  1. 经办人上传发货签收单或合同单据图片
  2. OCR 服务提取物资名称、规格、数量与到货单位
  3. 语义纠错模块将物料简称自动校准为标准物料编码与规范名称
  4. 系统输出识别提取卡片并同步至订单预览区
  5. 经办人确认无误后点击一键提单
- `Excel 批量提单流程`：
  1. 经办人上传包含多笔采购/销售订单的 Excel 文件
  2. 系统按行并发解析并校验合同号与数量规范
  3. 界面展示批量明细列表，对异常行标注预警状态
  4. 经办人针对异常行进行行内核实修改
  5. 点击批量提交，系统并发创建正式商贸订单

#### 2.10.8 单据输出与履约追溯格式

### 2.11 智能问询笔录平台

  - 左栏（正式问答区）：按大纲章节（固定开头、接触引流、被骗经过、资金损失、证据补充）组织卡片流，支持问题行内编辑、答案录入、新增/删除问答与来源标记

  - 右栏（五流证据区）：展示人员流、通信流、网络流、资金流、寄递流五个卡片，实时呈现覆盖进度、状态标签（已收集/需补充/重点缺口/不涉及）与证据摘要
  - 辅助材料抽屉：右侧滑出抽屉，提供材料拖拽上传与列表，明确物理隔离于问答正文
- `笔录文书预览与导出页`：展示标准红头格式询问笔录全文（红头标题、案件信息、问答正文、落款信息），提供 DOCX 导出与返回工作台入口
- `历史笔录导入与回溯页`：支持上传已有笔录文件或粘贴文本，自动解析提取问答对，生成五流证据分析报告并转存为新问询会话

#### 2.11.4 问询流转与五流研判体系
- 四阶段工作流断点续问机制：
  - 每个笔录任务持久化保存当前阶段标识：`intake`（接报录入）、`templates`（模板选择）、`inquiry`（问询进行中）、`completed`（已完成问询）
  - 点击“继续询问”时，系统识别阶段并精准恢复工作界面，保留已录入的表单、选定模板、问答内容与附件状态
- 19 类电信网络诈骗模板体系：
  - 覆盖冒充电商物流客服、网络婚恋交友、虚假投资理财、虚假征信、刷单返利、冒充公检法等 19 类常见电诈案由及通用模板
  - 每类模板预置专属问题集与特征信号词，基于案情事实文本自动加权计算匹配推荐度
- 五流全要素调查与缺口定位规则：
  - `人员流`：受害人身份、嫌疑人自称身份、代办人、团伙角色
  - `通信流`：涉案主叫/被叫电话、通话时长、通话时段、涉案短信

  - `寄递流`：快递单号、寄件人、收件人、收发地址、涉案包裹
  - 录入答复时异步抽取要素，当资金流等核心要素未满足时自动标记为“重点缺口”，并在中栏置顶生成追问建议
- 证据材料隔离与文书合规导出规则：
  - 辅助材料仅作为研判算法输入，严禁静默拼接插入正式笔录问答列表中，确保执法程序合法性

#### 2.11.7 核心业务流程
- `接报建档与外部案件同步流程`：
  1. 民警在笔录列表页点击“新增笔录”调起录入模态框
  2. 点击“一键同步其他系统信息”，输入案件编号或报案人检索外部系统数据
  3. 选中匹配案件并确认，系统自动将外部案情、受害人、办案单位回填至表单
  4. 民警核对后点击“进入模板选择”，系统保存接报草稿并流转至模板选择界面
- `AI 智能推荐与多模板选定流程`：
  1. 系统分析案情文本与特征词，调用分类推荐模型
  2. 界面展示 TOP 推荐模板及匹配度评分，并提供全量模板库检索
  3. 民警勾选一个或多个适用的涉诈案由模板
  4. 点击“确认模板并开始问询”，系统装配问询大纲章节与预设问题集，进入三栏工作台
- `三栏交互式问询与五流闭环流程`：
  1. 民警依据左栏大纲向受害人发问，行内录入或修改答复内容
  2. 系统根据录入答复实时提取要素，动态刷新右栏“五流”覆盖度统计
  3. 识别到关键要素缺失时，系统在中栏生成追问建议与推荐问题
  4. 民警核实后点击“加入问询”，推荐问题自动追加至左栏对应章节
  5. 涉及转账凭证等材料时，民警拉起材料抽屉上传附件，附件内容物理隔离于正式问答
  6. 要素采集完备后，民警点击“完成问询”，系统封存笔录数据并进入预览界面
- `文书生成与导出流转流程`：
  1. 系统读取笔录会话已作答的问答项列表与案件主数据
  2. 依据公安机关询问笔录排版规范构建段落文档流，过滤未作答空白项
  3. 排版生成符合文印标准样式的 DOCX 文书
  4. 民警核对在线预览效果后，点击“导出笔录”下载 Word 文档供签字确认

#### 2.11.8 笔录文书与证据研判输出格式
- `标准询问笔录文书（DOCX）`：红头文印标题、案件基本信息（时间/地点/询问人/被询问人）、正文（分章节问答对、粗体“问：”与正体“答：”）、被询问人核对签名区与办案人员署名区
- `五流证据要素覆盖表`：人员流、通信流、网络流、资金流、寄递流各项收集状态、已提取证据摘要（如转账时间、对方卡号、流水号）与重点缺口清单
- `AI 侦查研判指引报告`：案由判定结论、判定依据支撑链、嫌疑人画像推断、下游资金链拦截建议与后续补充侦查指引
- `操作审计流水记录`：案件编号、警员警号、操作类型（创建/修改/采纳建议/上传材料/导出文书）、操作时间戳与变更指纹

- 能上传辅助材料并确保与正式笔录问答内容保持物理隔离

- 能生成格式合规的 DOCX 笔录文件并成功下载，文书中包含规范红头、案由信息与“问/答”正文排版
- 能通过至少一个典型业务场景完成端到端全流程问询演示

## 3. 其他工具开发
### 通用开发要求
- 基础交付：每个工具至少支持一种实际数据输入方式，输出结构化结果、判断依据和处理建议
- 结果验证：提供可直接运行的演示数据和完整操作流程，支持查看输入、分析结果和异常提示
- 按需建设：涉及付款、审批、录用、处罚或敏感数据的工具增加人工复核、权限控制和操作记录，其他工具不强制实现完整管理流程

### 3.1 行政管理
#### 3.1.1 会议纪要与行动项跟踪器
- 要解决的问题：会议结束后行动项容易漏跟，责任人、截止时间和后续状态无法持续追踪
- 工具功能：从单次会议的录音转写或会议纪要中提取结论、待办、责任人和截止时间，生成会议行动项清单并跟踪完成状态

#### 3.1.2 资产异常巡检助手
- 要解决的问题：办公资产领用、归还、闲置状态靠人工表格维护，容易出现账实不符
- 工具功能：结合资产台账、扫码盘点记录、资产照片和维修记录，识别超期未还、长期闲置、重复领用、标签异常和盘点差异

### 3.2 人力资源
#### 3.2.1 候选人匹配筛查助手
- 要解决的问题：简历筛选依赖人工阅读，容易漏掉关键经历或忽略硬性条件
- 工具功能：根据岗位要求提取技能、年限、项目经历和风险点，输出匹配评分和待复核项

#### 3.2.2 面试一致性评估助手
- 要解决的问题：多轮面试评价标准不统一，面试官评分口径和证据充分性难以横向比较
- 工具功能：对接岗位能力模型、面试题库和多轮面试记录，检测评分偏差、证据不足、追问遗漏和评价冲突

### 3.3 财务管理
#### 3.3.1 发票报销审核助手
- 要解决的问题：报销审核需要反复核对发票、审批单和预算规则，人工审核耗时且容易漏检
- 工具功能：识别发票、行程单和审批单，对照报销制度、预算与历史入账记录校验材料完整性和财务合规性，推荐费用科目并输出通过、退回或人工复核结论

#### 3.3.2 预算执行偏差监控助手
- 要解决的问题：部门、项目和费用科目的实际支出偏离预算后难以及时发现
- 工具功能：按部门、项目、费用科目和期间对比预算与实际支出，识别超预算、执行进度异常和异常增长，输出偏差金额、偏差比例和责任范围

#### 3.3.3 应收账款逾期预警助手
- 要解决的问题：应收账款逾期会影响现金流，人工跟踪容易遗漏高风险客户
- 工具功能：结合应收账龄、合同账期、客户历史付款和催收记录，预测逾期风险并输出高风险客户、应收金额、预计逾期时间和催收优先级

### 3.4 法务管理
#### 3.4.1 合同签署前风险审查助手
- 要解决的问题：合同风险点分散在付款、违约、保密、知识产权等条款中，人工审查容易漏掉关键风险
- 工具功能：识别高风险条款，并按风险等级、影响范围和建议处理方式输出审查结果

#### 3.4.2 合同修订差异审查助手
- 要解决的问题：合同多轮修改后很难看清关键变化
- 工具功能：标记新增、删除、修改条款，并提示对责任、金额、期限和违约后果的影响

#### 3.4.3 合同签署后履约跟踪器
- 要解决的问题：合同签完后付款、交付、验收、续约等关键义务容易没人跟
- 工具功能：抽取合同中的付款、交付、验收、续约、终止等节点并生成提醒

### 3.5 采购管理
#### 3.5.1 供应商准入与履约评估助手
- 要解决的问题：供应商比价不只看价格，还要兼顾交期、付款、历史交付和售后
- 工具功能：在供应商准入和复评阶段汇总报价、资质、历史交付、质量与售后记录，输出分项评分、准入建议和履约风险

#### 3.5.2 采购申请完整性检查助手
- 要解决的问题：采购需求描述不清会导致反复补充信息，影响询价和审批效率
- 工具功能：在询价前对照历史采购、库存、预算和验收规则检查采购申请，识别缺失字段、规格歧义和异常数量，生成补充确认清单

#### 3.5.3 采购合同订单发票匹配助手
- 要解决的问题：采购合同、订单、发票之间容易出现金额或交期不一致
- 工具功能：从非结构化合同、订单和发票中识别供应商、金额、数量、交期等字段，自动比对并标记差异

### 3.6 销售管理
#### 3.6.1 销售商机停滞风险分析助手
- 要解决的问题：商机停滞、关键人缺失或竞品介入后，销售往往发现较晚
- 工具功能：识别长时间无进展、关键人缺失、预算不明确、竞品介入和报价异常

#### 3.6.2 销售报价与折扣合规检查助手
- 要解决的问题：报价与客户需求、折扣权限、合同条款之间容易不一致
- 工具功能：校验报价单、折扣、产品配置和审批权限，标记不合规项

### 3.7 客户服务
#### 3.7.1 全渠道反馈工单化与智能分派助手
- 要解决的问题：用户反馈分散在客服会话、评论、社群和问卷中，人工建单、去重、分类和分派效率低
- 工具功能：汇集多渠道反馈并完成聚类、去重和工单转换，根据问题描述、产品、订单与历史处理记录判断类别、优先级和负责团队

#### 3.7.2 高风险投诉升级预警助手
- 要解决的问题：高风险投诉没有及时升级，容易演变为舆情或重大客户风险
- 工具功能：识别负面情绪、重复投诉、金额争议、舆情风险和 SLA 超时风险

#### 3.7.3 客服工单共性问题根因分析助手
- 要解决的问题：同类问题重复发生但难以及时反馈给产品或运营
- 工具功能：对已处理工单进行主题聚类，关联订单、产品版本和处理结果，识别重复问题、可能根因与影响范围，并生成产品或运营改进待办

### 3.8 市场营销
#### 3.8.1 广告投放异常诊断助手
- 要解决的问题：投放效果波动大，人工排查点击率、转化率和成本异常耗时
- 工具功能：对接广告平台的账户、计划、素材和人群数据，识别点击率、转化率和成本异常，输出异常层级、影响范围、可能原因和调整建议

#### 3.8.2 市场调研洞察分析助手
- 要解决的问题：问卷和访谈数据量大，目标人群的需求差异、购买动机和市场机会难以提炼
- 工具功能：结合问卷、访谈和用户画像，按人群、场景、需求、购买动机与阻碍因素分类，输出细分人群特征、市场洞察和机会方向

### 3.9 业务运营
#### 3.9.1 用户运营漏斗异常诊断助手
- 要解决的问题：获客、激活、转化、留存和复购环节发生异常后，运营人员难以快速定位受影响的人群和流程节点
- 工具功能：监控访问、注册、激活、转化、留存和复购指标，按人群、渠道、地区、版本与时间拆解异常，输出漏斗损耗节点和运营待办

#### 3.9.2 运营活动全周期评估助手
- 要解决的问题：活动立项缺少数据依据，活动结束后也难以判断效果不佳的具体原因
- 工具功能：面向促销、拉新、召回和会员活动，活动前根据历史数据、预算、目标人群与规则评估可行性，活动后结合成本、漏斗和用户行为输出效果与归因结果

### 3.10 产品管理
#### 3.10.1 产品需求价值评估助手
- 要解决的问题：需求优先级容易被主观判断影响，难以解释取舍依据
- 工具功能：对已进入需求池的产品需求，结合用户覆盖、业务价值、战略匹配度、实现成本和风险形成价值评分与优先级建议

#### 3.10.2 产品交付物一致性检查助手
- 要解决的问题：需求、原型、接口、埋点和测试用例之间容易不一致，导致上线后返工
- 工具功能：对接 PRD、原型说明、接口文档、埋点方案和测试用例，检查字段、流程、权限、异常状态和验收条件是否一致

#### 3.10.3 上线版本问题归因助手
- 要解决的问题：上线后问题难以快速归因到需求、设计还是实现
- 工具功能：针对指定上线版本关联异常日志、监控指标、工单、代码变更、测试记录和需求文档，判断问题来源属于需求遗漏、设计缺陷、实现错误、配置变更或数据异常

### 3.11 教学实施
#### 3.11.1 教学学情诊断与分层练习助手
- 要解决的问题：作业、随堂测和课堂互动数据分散，教师难以及时识别个人与班级的知识点缺口并安排差异化练习
- 工具功能：结合评分标准、作业、随堂测、课堂互动和课程进度，识别学生错因、个人薄弱点与班级共性卡点，生成补讲清单和分层练习建议

### 3.12 培训运营
#### 3.12.1 培训结业与发证风险预警助手
- 要解决的问题：报名、出勤、测评和证书数据分散，学员是否满足结业或发证条件难以及时判断
- 工具功能：结合报名信息、出勤记录、考试成绩、作业和发证规则，识别结业风险、证书发放异常和需要运营跟进的学员

#### 3.12.2 培训成效与课程改进分析助手
- 要解决的问题：培训效果只看满意度，测评、业务表现和学员反馈难以形成统一的改进依据
- 工具功能：对比课前测评、课后测评、作业和业务指标变化，结合反馈内容、课程版本与讲师安排分析问题来源，输出能力提升结果、未达标人群和课程改进待办

### 3.13 团队管理
#### 3.13.1 团队人员产能与负载分析助手
- 要解决的问题：人员负载不均衡，容易出现关键人过载或资源闲置
- 工具功能：汇总成员在多个项目和日常工作中的任务数量、优先级、计划工时与截止时间，输出个人负载、团队可用产能和任务调配建议

#### 3.13.2 绩效证据归集与事实核验助手
- 要解决的问题：绩效评价缺少持续积累的可验证证据，评价表述与实际贡献也难以核对
- 工具功能：关联目标、任务、交付物、协作记录和业务指标，按人员与考核周期生成证据档案，校验评价中的事实、时间、贡献和结果并标记证据缺口

### 3.14 项目管理
#### 3.14.1 单项目进度风险预测助手
- 要解决的问题：项目延期风险通常到临近交付才暴露
- 工具功能：针对单个项目分析里程碑、关键路径、任务依赖、完成率和变更频率，预测延期风险并输出受影响里程碑、交付物和赶工优先级

#### 3.14.2 项目需求变更影响评估助手
- 要解决的问题：需求变更导致范围蔓延，影响排期和成本
- 工具功能：对比变更前后的需求范围，识别受影响的任务、里程碑、接口、测试、人员、成本和交付物，输出变更影响清单与重新排期建议

#### 3.14.3 跨部门协作阻塞诊断助手
- 要解决的问题：跨部门协作责任边界不清，阻塞事项容易长期无人处理
- 工具功能：从跨部门任务流转、审批和沟通记录中识别未确认责任人、等待外部输入、等待审批和长期无响应事项，输出阻塞链路与升级对象

### 3.15 经营分析
#### 3.15.1 经营财务指标异常诊断助手
- 要解决的问题：收入、毛利、费用、库存周转和经营现金流等公司级指标异常跨越多个系统，经营分析人员难以及时定位来源
- 工具功能：汇总销售、成本、费用、库存和现金流数据，监控公司级经营财务指标，按业务线、区域、产品和期间拆解异常，输出经营影响与管理层关注事项

#### 3.15.2 经营目标情景测算助手
- 要解决的问题：年度目标和经营调整缺少收入、成本、现金流与资源约束的联动测算
- 工具功能：输入收入增长、价格、成本、人员和预算等变量，生成不同情景下的利润、现金流、资源缺口、风险阈值和目标达成情况对比

#### 3.15.3 竞品异动经营影响评估助手
- 要解决的问题：竞品价格、渠道和产品变化影响业务但难以及时量化
- 工具功能：跟踪竞品变化并关联自身销售、客诉和市场数据判断影响范围

## 4. 模型微调
### 4.1 知识库项目模型微调
- 模型用途：根据检索系统召回的文档片段、表格内容、制度条款或产品资料生成答案
- 微调目标：提升模型基于检索内容作答的忠实性、完整性、可追溯性和拒答能力

#### 4.1.1 行业术语与回答格式适配能力
- 需要提升的能力：按照知识库所属行业的术语、口径和输出格式回答，例如制度解释、产品说明、操作步骤、故障处理
- 训练数据：行业问答样例、标准术语表、不同格式的答案模板
- 评估重点：术语是否准确，格式是否稳定，回答是否符合业务口径

#### 4.1.2 检索内容忠实回答能力
- 需要提升的能力：严格依据检索结果回答问题，避免编造未出现在资料中的事实、数字、政策和结论
- 训练数据：用户问题、检索片段、标准答案、不可回答样例
- 评估重点：答案是否有依据、是否引入幻觉、是否遗漏关键条件

#### 4.1.3 多片段信息整合能力
- 需要提升的能力：从多个检索片段中合并同一主题的信息，处理上下文分散、表述不一致和跨段落引用
- 训练数据：多段检索结果、跨文档问题、整合后的标准答案
- 评估重点：信息整合是否完整，是否能区分主次、条件和适用范围

#### 4.1.4 证据引用与出处标注能力
- 需要提升的能力：在答案中标注依据来源，说明结论来自哪些检索片段或文档条款
- 训练数据：带来源编号的检索结果、带引用标注的答案样例
- 评估重点：引用是否准确，答案内容和引用证据是否一致

#### 4.1.5 资料不足时的拒答能力
- 需要提升的能力：当检索结果不足、无关或互相矛盾时，不强行回答，并提示缺少哪些信息
- 训练数据：无召回、弱相关召回、冲突召回和标准拒答样例
- 评估重点：拒答是否及时，是否能指出缺失信息和下一步补充方向

### 4.2 问数项目模型微调
- 模型用途：根据检索出的表结构、字段信息、字段值、指标定义和计算规则生成 SQL
- 微调目标：提升模型从自然语言问题到可执行 SQL 的字段匹配、指标计算、条件构造和澄清能力

#### 4.2.1 业务问题到字段映射能力
- 需要提升的能力：将用户自然语言中的业务概念映射到正确的数据表、字段、枚举值和时间字段
- 训练数据：用户问题、检索出的 schema、字段说明、字段值样例、标准 SQL
- 评估重点：表字段选择是否正确，过滤条件是否符合业务含义

#### 4.2.2 字段值识别与标准化能力
- 需要提升的能力：将用户输入中的别名、简称、口语表达映射为数据库中的标准字段值
- 训练数据：字段值字典、同义词、历史查询问题、标准 SQL
- 评估重点：枚举值是否匹配，模糊值是否需要澄清，是否误用不存在的字段值

#### 4.2.3 指标口径理解与计算能力
- 需要提升的能力：根据检索出的指标定义生成正确的聚合、计算公式、分母分子、去重逻辑和时间口径
- 训练数据：指标说明、计算规则、用户问题、标准 SQL
- 评估重点：指标口径是否正确，聚合函数、去重和时间范围是否准确

#### 4.2.4 查询意图澄清能力
- 需要提升的能力：当用户问题缺少时间范围、统计粒度、指标口径或筛选条件时，主动提出澄清问题
- 训练数据：信息不完整的问题、澄清问题样例、补充信息后的 SQL
- 评估重点：是否能识别缺失条件，澄清问题是否具体可回答

#### 4.2.5 多表关联与查询条件生成能力
- 需要提升的能力：根据主外键、业务关联关系和筛选条件生成 join、where、group by、having、order by 等 SQL 结构
- 训练数据：多表 schema、关联关系、复杂查询问题、标准 SQL
- 评估重点：join 路径是否正确，条件是否遗漏，分组粒度是否合理

#### 4.2.6 SQL 安全与方言适配能力
- 需要提升的能力：生成只读查询语句，适配目标数据库 SQL 方言，避免删除、更新、越权查询和危险函数
- 训练数据：不同数据库方言样例、安全 SQL 样例、危险 SQL 反例
- 评估重点：SQL 是否可执行，是否符合方言，是否满足只读和权限约束

### 4.3 客服项目模型微调
- 模型用途：识别用户意图，进入对应业务流程，抽取槽位信息，并在必要时澄清问题或转人工处理
- 微调目标：提升模型在多轮客服场景中的意图识别、槽位抽取、流程控制、澄清和异常处理能力

#### 4.3.1 用户意图识别能力
- 需要提升的能力：识别用户消息对应的业务意图，例如查询订单、修改信息、申请退款、投诉升级、人工转接
- 训练数据：用户原始消息、意图标签、多意图样例、相似意图区分样例
- 评估重点：意图分类是否准确，是否能识别多意图和模糊意图

#### 4.3.2 槽位信息抽取能力
- 需要提升的能力：从用户消息中抽取订单号、手机号、商品名、时间、地址、金额、问题类型等关键槽位
- 训练数据：用户消息、槽位标注、缺失槽位样例、错误槽位反例
- 评估重点：槽位是否完整、准确，是否能识别缺失和冲突信息

#### 4.3.3 澄清问题生成能力
- 需要提升的能力：当用户诉求不清、槽位缺失或多个流程都可能匹配时，提出具体澄清问题
- 训练数据：模糊用户消息、缺失槽位状态、标准澄清话术
- 评估重点：澄清问题是否必要、具体、一次只问关键缺失项

#### 4.3.4 多轮流程状态管理能力
- 需要提升的能力：根据当前流程、已收集槽位和用户补充信息决定下一步动作
- 训练数据：多轮对话、流程节点、槽位状态、下一步动作标注
- 评估重点：流程跳转是否正确，是否能保持上下文，不重复询问已提供信息

#### 4.3.5 异常处理与人工升级能力
- 需要提升的能力：识别用户情绪升级、规则不可处理、信息冲突、流程无法继续等情况，并进入兜底或人工流程
- 训练数据：异常对话、信息冲突样例、投诉升级样例、人工转接样例
- 评估重点：是否能及时升级，是否避免错误承诺，是否保留必要上下文给人工客服
